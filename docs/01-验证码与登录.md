## P1-01 发送验证码

修改 `hm-dianping/src/main/java/com/hmdp/service/impl/UserServiceImpl.java` 中的 `sendCode` 方法。
接口已接好：`POST /user/code?phone=13800138000`，不需要改 Controller。

### 输入与输出

输入是手机号字符串。手机号不合法时返回 `Result.fail(...)`；合法且保存验证码成功后返回 `Result.ok()`。
验证码通过日志模拟发送，不调用真实短信服务，也不把验证码放进接口响应。

### 自己完成的步骤

1. 阅读 `RegexUtils.isPhoneInvalid`，先处理非法手机号。
2. 生成六位数字字符串，注意 `012345` 这种有前导零的情况。
3. 拼接 key：`RedisConstants.LOGIN_CODE_KEY + phone`。
4. 把验证码写入 Redis，使用 `LOGIN_CODE_TTL`，单位为分钟。
5. 打印 debug 日志模拟发送，然后返回成功。

可以查阅的工具：Hutool 的 `RandomUtil`、`StringRedisTemplate.opsForValue()`、`TimeUnit`。
这里保留方法参数中的 HttpSession 只是兼容课程接口，本练习的验证码存在 Redis 中。

### 验收

先确认 Redis 已启动且配置正确，重新构建或重新运行后端。

```powershell
curl.exe -X POST "http://127.0.0.1:18081/user/code?phone=123"
curl.exe -X POST "http://127.0.0.1:18081/user/code?phone=13800138000"
```

| 场景 | 预期 |
| --- | --- |
| 非法手机号 | success=false；不产生对应验证码 key |
| 合法手机号 | success=true；日志中能看到六位验证码 |
| 查询 Redis | key 为 dp:practice:login:code:13800138000；值与日志一致 |
| 查询 TTL | 生成后立刻查询应大于 0 且不超过 120 秒 |
| 等待过期 | 两分钟后该 key 不存在 |

在 Redis 客户端连接本机 **16379** 端口，使用本机配置中的密码认证，选择 DB 0，然后执行：

```text
GET dp:practice:login:code:13800138000
TTL dp:practice:login:code:13800138000
```

把正常和错误输入都验证过，再勾选学习进度。验证码接口不依赖数据库，可在练习库导入前先完成。

## P1-02 验证码登录（下一步）

接口：`POST /user/login`，JSON 输入：

```json
{"phone":"13800138000","code":"从日志获取的验证码"}
```

实现要求：校验手机号及验证码；用户不存在则创建，存在则复用；生成随机 token；只把 UserDTO 中的必要字段转换为字符串并存入 Redis Hash；设置 30 分钟有效期；成功后删除验证码；返回 token 字符串。
登录 key：`dp:practice:login:token:<token>`。登录时不要向客户端返回 password 或完整 User 实体。
异常或失败分支不应创建用户、写 token 或误删尚未成功使用的验证码。

验收：错误验证码、过期验证码、首次登录、再次登录不重复建用户、token 的 Hash 字段与 TTL、成功后验证码不能再次使用。
可使用 Apifox 发 JSON 请求。当前先不加入拦截器；能通过 token 获取当前用户属于 P2。
