# 点评后端重写开发说明

## 1. 当前起点

项目目录：`D:/Projects/Java/Redis`。旧工程 `D:/Projects/Java/DianPing` 保持原样。
目标是让你独立重写核心业务，不必重新制作前端和机械重复实体类。

已保留：前端与图片、实体类、DTO、Mapper、MyBatis 分页配置、统一响应、异常处理、基础列表查询、优惠券创建辅助代码、UserHolder。
已清空：验证码发送、验证码登录、订单 ID 生成器；发布笔记、点赞、我的笔记改成明确的待实现接口。
原本尚未完成的当前用户、退出、秒杀下单继续保留待实现状态。
商户查询目前直接查数据库，商户更新直接写数据库；阶段 3 再把业务移至 Service 并加入缓存。
没有预置登录拦截器、商户缓存、Lua、消息消费者或秒杀答案。

这次先恢复课程练习环境，框架版本升级另开任务。

## 3. 首次启动

脚本已按使用者拆分：你日常使用 `scripts/user/`；Agent 的后台后端启停使用 `scripts/agent/`。完整参数和交接规则见 [脚本使用说明](../scripts/README.md)。

0. 如果助手已在后台启动后端，先执行 `scripts/agent/stop-backend.ps1`，再用 IDEA 启动，避免占用同一个端口。
1. 用 IDEA 打开 `D:/Projects/Java/Redis/hm-dianping`，作为 Maven 项目加载。
2. 确保 MySQL 服务运行。练习版 Redis 使用独立端口 16379，可运行 `scripts/user/start-redis.ps1` 启动；私有配置在 `.local/redis.conf`，数据在 `.run/redis-data`。可运行 `scripts/user/check-env.ps1` 检查端口。
3. 首次准备时助手已创建并导入练习库；日常开发直接使用，不重复初始化。换到全新环境时，再在数据库工具中执行 `database/01-init-practice.sql`。脚本会明确创建并选择 `dianping_practice`，重建该练习库的课程表。首次导入一次即可；重复运行会清空这套练习表中的修改，不要在完成练习后随意重跑。
4. 启动后端。IDEA 运行 `HmDianPingApplication`，工作目录设为 `D:/Projects/Java/Redis/hm-dianping`；或者在项目根目录执行：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\user\start-backend.ps1 -Build
```

5. 另开终端启动前端：

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\user\start-frontend.ps1
```

6. 打开 `http://127.0.0.1:18080`。`/api` 请求由 Nginx 转发到后端，前端源码无需改地址。

重新修改 Java 代码后，IDEA 重新运行，或停止旧后端并用 `-Build` 重建再运行。没有 `-Build` 时脚本会使用已有 JAR。
后端前台运行时用 Ctrl+C 停止；练习版 Redis 使用 `scripts/user/stop-redis.ps1` 保存数据并停止；前端使用 `scripts/user/stop-frontend.ps1`，仅停止本练习版 Nginx。
如果助手已在后台启动后端，可使用 `scripts/agent/stop-backend.ps1`；该脚本会校验 PID 对应的启动命令。

## 4. 起点验收

- `GET /practice/status`：返回练习工程标识。这仅证明应用有响应，不证明 MySQL、Redis 连通。
- `GET /shop-type/list`、`GET /shop/1`：在导入数据库后能返回课程数据，证明数据库查询可用。
- `POST /user/code`、`POST /user/login`：当前返回 `success:false` 和“待实现”，是预期行为。
- 登录、发布、点赞、秒杀等页面在对应阶段完成前不能走通，是有意保留的练习空位。
- 应用启动不会自动执行 SQL，不会清 Redis，也不会自动向 Redis 写登录数据。

## 5. 分阶段开发

| 阶段 | 写什么 | 完成标准 |
| --- | --- | --- |
| P1 | 验证码与登录 | 非法手机号被拒绝、验证码有 TTL、首次登录创建用户、再次登录复用、token 能查到用户信息 |
| P2 | 登录状态 | 读取 authorization 请求头、恢复 UserHolder、刷新有效期、清理 ThreadLocal、当前用户、退出 |
| P3 | 商户缓存 | 查询移至 Service、Cache Aside、过期时间、空值缓存、更新后删除缓存；再学穿透与击穿 |
| P4 | 数据库下单 | 活动时间与库存校验、事务、一人一单、条件扣库存、ID 生成；并发验证不超卖 |
| P5 | 秒杀优化 | 按需求逐步引入分布式锁、Lua、异步处理，考虑重复消息、失败重试和数据一致性 |
| P6 | 社交与统计 | 点赞/取消、关注、Feed、签到、附近商户，按兴趣逐个练习 |

阶段 2 的拦截器必须放行验证码、登录和公开查询。登录状态可以每次读取并刷新，身份校验只对需要登录的接口执行。
Redis key 常量已加练习前缀。验证码 TTL 为 2 分钟，登录 TTL 为 30 分钟，商户缓存 TTL 为 30 分钟；调用时明确使用 `TimeUnit.MINUTES`。
不要用旧教程中不带前缀的字符串；不执行 FLUSHDB、FLUSHALL。
P1 的验证码登录先使用同步流程；原子消费验证码、并发注册冲突和频率限制列入后续加固，不把第一课扩成并发专题。

## 6. 看代码的顺序

1. `controller/UserController.java`：请求路径与参数。
2. `dto/LoginFormDTO.java`、`dto/Result.java`：输入和输出。
3. `service/IUserService.java` 与 `service/impl/UserServiceImpl.java`：业务入口与当前 TODO。
4. `utils/RedisConstants.java`、`utils/RegexUtils.java`：常量和手机号校验工具。
5. `entity/User.java`、`dto/UserDTO.java`：数据库对象与返回字段的区别。

上面 Java 路径均相对 `hm-dianping/src/main/java/com/hmdp/`。

## 7. 带练方式

每次只做一个小任务。先说清楚输入、输出、数据位置，再写代码，跑通正常和失败场景，最后解释关键选择。
遇到卡点时带上任务编号、相关方法、错误信息和自己的判断。助手默认给提示和检查，不直接填完后续所有 TODO。
完成后在 `学习进度.md` 记录证据；当前第一项是 P1-01，具体要求见 `01-验证码与登录.md`。

## 8. 常见情况

- 端口占用：先确认是不是本练习工程已启动，不停止不明进程。
- 数据库不存在：执行本项目的独立练习 SQL，核对 URL 中的库名。
- Access denied / Redis NOAUTH：核对本机配置；错误日志和截图中隐藏密码。
- 页面“功能未实现”：当前阶段的正常响应，按任务编号实现。
- 本机 MySQL 使用 caching_sha2_password，已在本地开发 URL 中增加 allowPublicKeyRetrieval=true；未更改数据库用户或全局认证设置。
- 图片上传使用相对目录，需以 hm-dianping 为工作目录；也可以通过 JVM 参数 `-Dhmdp.image-dir=绝对图片目录` 指定。
